# Contributing

Thanks for helping. [PLAN.md](PLAN.md) has the roadmap and the reasons behind each decision, so start there.

- **Keep the code easy for beginners to read.** Plain bash, nothing clever.
- **Keep private details out.** Use `gitlab.example.com`, `lab-host`, and the `192.0.2.x` documentation addresses in files, screenshots, and commit messages.
- **Send changes as pull requests.** `main` only changes through a pull request, and pull requests are squash merged.
- **Tom's story stays as written.** Changes to the README's prose are limited to technical corrections.
